# Security Policy

FilaForge Studio is not yet a stable production release. The package includes security controls, but the host application must configure authorization, tenancy, session protection, storage, CSP, and public routes correctly. Passing the current test suite is not a security audit.

## Reporting a vulnerability

Do not publish credentials, customer data, private URLs, or working exploit details in a public issue.

A private security reporting address has not yet been published. Until the maintainer adds a monitored contact method, contact the repository owner through a private channel associated with the repository. Include a concise impact description and steps to reproduce using sanitized data. Do not send production secrets or customer records.

There is no response SLA or supported production version declared yet. The maintainer should publish a monitored contact and response timeline before a public stable release.

See the [security guide](docs/security.md) for current security boundaries and host deployment responsibilities.
